# 项目需求与范围

本项目从只读上游与静态扩展清单选择功能，为多个独立配置方案生成 SurfingKeys 自定义脚本。用户维护 personal/work 等方案，通过 CLI 或项目 SKILL 创建和更新选择，构建结果可解释、可追踪且可恢复。

## 当前支持范围

固定 `b0o-v1` 上游版本的 Amazon 站点功能、DuckDuckGo 搜索、core.openLink，以及显式列出的本地目录/Git submodule 扩展。方案使用 JSON、单父继承和 minimal base。公开 CLI 包括 catalog、validate、explain、build单方案/批量、compare与显式来源锁刷新，操作方法见 [快速开始](quickstart.md)。

## 功能和质量契约

| ID | 要求 |
| --- | --- |
| FR-001 | 上游只读且固定版本，使用隔离生成副本，不启动上游 gulp流水线 |
| FR-002 | 功能选择与代码依赖分离，保留传递实现并解释原因，不自动启用依赖提供者注册 |
| FR-003 | 扩展按静态清单发现、按需分析和加入，未选入口不执行 |
| FR-004 | 多方案单父继承、差量选择、字段来源解释，单个/批量构建产物隔离 |
| FR-005 | 功能ID、搜索alias、有效键与显式贡献覆盖可预测，冲突和前缀有诊断 |
| FR-006 | catalog/validate/explain/build/compare 输出结构化结果与错误码 |
| FR-007 | 创建/更新方案 SKILL 使用真实catalog，保留用户意图与非目标父/来源输入 |
| FR-008 | 来源变化显式确认，旧产物保留，失败不损坏上一成功结果 |
| NFR-001 | 离线构建、规范身份、产物摘要及许可入口；同一身份输入应可复现 |
| NFR-002 | AST转换保守，维持作用域、依赖与语句顺序，未知模式显式失败 |
| NFR-003 | 单方案锁、独立staging、不可变build与原子current更新，批量部分失败可观测 |
| NFR-004 | 配置数据不执行JS，路径与私有输入受限；扩展源码受信任，不宣称安全沙箱 |

## 非目标与后续方向

当前不支持通用 JavaScript 程序切片、任意上游SHA、upstream-global、主题/DOI功能目录、扩展npm来源、浏览器动态下载模组、自动安装/部署、读取既有conf.priv或配置密钥。公共util可能保守保留，不保证每个npm依赖都最小化。

扩展更多上游功能、util精细裁剪及其他来源类型需先补适配器、schema/迁移与行为测试；未来方向不作为当前可选ID或已实现命令承诺。详细约束见 [架构](design.md)和 [设计决策](decisions.md)，维护检查见 [开发与测试](development.md)。
